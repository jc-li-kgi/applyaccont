第一次安裝 每人每台電腦一次

  1. 安裝 Git設計師工程師
  2. 安裝 nvm，再用它安裝 Node.js 22

    Windows 用 nvm-windows。不要用 npm install -g 裝全域套件。

    nvm install 22
  3. 安裝 VS Code 與擴充套件「Vue - Official」
  4. 安裝 Claude Code，用公司帳號登入

    從組織 plugin 庫安裝 kgi-ui-kit，裡面有兩個 skill：generate-ui（生成介面）、sync-figma（從 Figma 補充 kit）。也可以在 Claude Code 從 /plugin 的 Marketplaces 加入組織 plugin 庫後執行：

    /plugin install kgi-ui-kit@claudeai-organization-library
  5. 只有要同步 Figma 的人：連上 Figmakit 維護者

    在 Claude Code 用 /mcp 連上 Figma 並登入。

開新專案 每個專案一次

  1. 在公司 Git 建立專案畫面 repokit 維護者

    例如 <子公司>-<專案>-screens。

  2. 放入 5 個檔案後 pushkit 維護者

    kit 用 git 網址加 tag 鎖定版本。範本展開如下。

  3. 本機跑一次 npm install，把 package-lock.json 一起 commitkit 維護者

    之後大家用 npm ci 照它安裝，版本完全一致。

5 個檔案的範本
package.json
{
  "name": "<子公司>-<專案>-screens",
  "private": true,
  "type": "module",
  "scripts": {

    "build": "nuxt build",
    "postinstall": "nuxt prepare",

  "dependencies": {
    "@kgi/ui-kit": "git+https://<公司 Git>/<群組>/kgi-ui-kit.git#v0.1.0",
    "nuxt": "~4.5.2",

}

CLAUDE.md（讓 Claude 讀到 kit 的規則；GitHub Copilot 不會讀這個檔）
# <專案名稱> 畫面

用 @kgi/ui-kit 做前端畫面，交給工程師。頁面放 `app/pages/`，一頁一個檔案。
- 生成頁面用 generate-ui skill；沒有安裝時，照 `node_modules/@kgi/ui-kit/plugins/kgi-ui-kit/skills/generate-ui/SKILL.md` 的流程。
- **不要修改 `node_modules/@kgi/ui-kit/`**。kit 缺元件或規則不清楚時，在頁面標 TODO 並在回報裡列出，由 kit 維護者更新。
- 交付前跑 `npm run check:tokens`。

@node_modules/@kgi/ui-kit/plugins/kgi-ui-kit/skills/generate-ui/rules.md

加入專案 每人每個專案一次

  1. 取得專案並安裝設計師
    git clone <專案畫面 repo 網址>
cd <專案資料夾>
nvm use
npm ci
  2. 確認跑得起來設計師
    npm run dev

    打開 http://localhost:3000。

每次做畫面

  1. 拉最新設計師

    git pull

  2. 開 branch設計師

    例如 design/loan-apply。先分好誰負責哪幾頁，一頁一個檔案，就不會衝突。

  3. 請 Claude 用 ui kit 生成介面Claude

    說「用 ui kit 生成介面…」或「用 kgi-ui-kit 做…」，generate-ui skill 會照這個順序做：

    讀描述／Figma→推斷頁面類型與版型→缺必要資訊時一次追問完→選元件→照 rules.md 寫頁面→檢查→回報推斷與預設

    描述可以照 page-spec.md 範本寫。間距、顏色、字級不會問，一律照規則。

  4. 看畫面設計師

    npm run dev，用 375／768／1024 寬度看手機、平板、桌機。

  5. 規範檢查自動

    npm run check:tokens：抓出寫死的數值、色碼、Tailwind 預設字級。

  6. commit、push、發 PR設計師
  7. 審核後合併kit 維護者

不熟 git，直接跟 Claude 說

「拉最新的」git pull
「開一個分支做借款申請」建 branch
「commit 並推上去發 PR」commit · push · PR
「有衝突，幫我看」比對兩邊並說明

只改 app/pages/（和必要的假資料檔），不改 kit。kit 缺元件或規則不清楚，請 Claude 在頁面標 TODO，再回報給 kit 維護者。

交給工程師

給不用給
專案 repo 網址 + branch 或 tag元件、CSS、guideline（工程師 npm ci 後就有）
kit repo 的讀取權限整包資料夾複本
  • kit 版本已寫在專案的 package.json，工程師拿到的是同一版 kit 與規則。
  • 規則與元件說明在 node_modules/@kgi/ui-kit/plugins/kgi-ui-kit/skills/generate-ui/rules.md；建議把 kit 的 Storybook（npm run build-storybook → storybook-static/）部署成內部網站給工程師、PM 查。
  • 頁面裡的文案、數值是假資料，標 // TODO: 待替換文案。

補 Foundation／元件 kit 維護者 · sync-figma skill

在 kgi-ui-kit repo 裡做（產品或畫面專案裡的 kit 在 node_modules，不能改）。給連結並說「從 Figma 補到 ui kit」「補 foundation」「更新元件」，sync-figma 會照下面的步驟做。

  1. 給 Figma section 連結kit 維護者
  2. 讀稿Claude

    Figma MCP：get_metadata、get_variable_defs、get_screenshot。只讀連結的 section、跳過隱藏圖層、只看實際套用的值。

  3. 回報差異Claude

    Figma 和 Guideline、元件不同的地方，只列出兩邊的值。

  4. 決定以誰為準kit 維護者

    guideline/ 只有維護者說要改時才改。

  5. 修改Claude
    • 改 Guideline：guideline/*
    • 改元件：app/components/<分類>/Kgi*.vue、stories/、app/kgi.ts
  6. 產生自動

    npm run theme（改了 guideline）、npm run components（改了元件或 story）

  7. 檢查自動

    npm run theme:check、npm run check:tokens、npm run typecheck

  8. Storybook 看畫面kit 維護者

    npm run storybook

  9. 記錄、commit、發版kit 維護者

    寫 CHANGELOG.md（Guideline 改動記在「規範」）。接著照「kit 發版與升級」。

kit 發版與升級

kit 發新版

  1. 更新 CHANGELOG.md 與 package.json 的 versionkit 維護者
  2. 打 tag、pushkit 維護者

    例如 v0.2.0。

  3. 有改 skill 就重新發佈 kgi-ui-kit pluginkit 維護者

    同時更新 plugin.json 的 version。

專案要升級 kit 時

  1. 把專案 package.json 的 #v0.1.0 改成新 tagkit 維護者
  2. npm installkit 維護者
  3. 看 CHANGELOG 的 ⚠️ 不相容變更，檢查畫面kit 維護者
  4. commit package.json 與 package-lock.jsonkit 維護者

專案不升級就維持舊版，不會被突然改壞。

AI 會讀的檔案

generate-ui 的檔案在 plugins/kgi-ui-kit/skills/generate-ui/；sync-figma 只有一個 SKILL.md（plugins/kgi-ui-kit/skills/sync-figma/），讀稿與規範也照同一份 rules.md。規則只有 rules.md 一份，CLAUDE.md、Storybook 的 Rules 頁都是引用它。

檔案內容維護方式
SKILL.md流程、推斷規則、必問、預設、追問規則手寫
rules.md唯一一份使用規範：class 寫法、禁止、顏色與交易狀態、字級、間距表、Grid、Figma 讀稿手寫，theme:check 會比對 guideline
components.md叫法 → 元件、選用規則、kit 還沒有的元件手寫
components-api.md每個元件的 props、v-model、事件、slot、說明自動 npm run components
page-spec.md頁面描述範本手寫

線上 plugin 只帶這個資料夾，不帶 CLAUDE.md、guideline/、元件原始碼。本機改了這些檔案，要重新發佈 plugin，其他專案才會讀到新版。

套件與資安

要做不要做
一個專案一個資料夾，各自 node_modules全域安裝（npm install -g）；要執行工具用 npx
用 nvm 切 Node 版本，專案放 .nvmrc同一個專案混用 npm／yarn／pnpm
平常用 npm ci（照 package-lock.json 安裝）刪掉或不 commit package-lock.json
新增套件先問 kit 維護者或 IT隨意 npm install <新套件>
定期跑 npm audit，結果給 IT 判斷npm audit fix --force（會升大版本，偏離規定的技術版本）
用 git clone 取得 kit／專案複製整包資料夾（會帶到 node_modules、.nuxt、.output、storybook-static）

安裝時會執行腳本的套件只有 3 個：@kgi/ui-kit（nuxt prepare）、esbuild、vue-demi。較新的 npm 會提示「install scripts not yet covered by allowScripts」，這 3 個是預期內的。
